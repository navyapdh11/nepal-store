- **No routing library** — manual view switching via `useState`

### Backend (Dual Implementation)

- `/api/auth/register` — in-memory user creation
- `/api/auth/login` — plaintext password comparison
- `/api/products` — reads `public/products.json`

**Vercel Serverless** (`api/`):
- Same endpoints, different code, different secrets
- `api/products.ts` — same JSON read with CDN caching

### Product Catalog
- `public/products.json` — 450 products (50 per category × 9 categories)
- Generated by `generate_catalog.cjs` using Unsplash images
- All products share identical description template
- Each product: `{ id, name, description, price, category, image, sizes, colors, isNew, rating, reviews }`

## 5. Security Findings

### CRITICAL
1. **Hardcoded JWT secret (Express):** `"nepal-store-secret"` in `server/auth.service.ts`
2. **Hardcoded JWT secret (Vercel):** `"nepal-store-secret-2026"` in `api/auth/*.ts`
3. **Plaintext password storage and comparison** — no bcrypt
4. **`.env` committed to git** — `DATABASE_URL="file:./dev.db"`
5. **Prisma: PostgreSQL schema vs SQLite `.env`** — contradiction

### HIGH
6. Prisma installed but NEVER used (zero `PrismaClient` imports)
7. No auth middleware on any route (`verify()` exists but never called)
8. All endpoints publicly accessible
9. No CORS middleware on Express server
10. No rate limiting
11. No input sanitization

### MEDIUM
12. `Math.random()` for user IDs (not cryptographically secure)
13. No password field in Prisma User model
14. Duplicate backend implementations (Express + Vercel)
15. `ignoreDeprecations: "6.0"` in tsconfig
16. No HTTPS enforcement
17. No security headers (helmet)
18. No error logging (catch blocks ignore errors)
